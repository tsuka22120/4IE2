# 水力発電適地選定システム - 想定Q&A集

このドキュメントは、プロジェクト発表時に想定される質問とその回答をまとめたものです。

## 1. プロジェクト概要・目的

**Q: このシステムの主な目的は何ですか？**
**A:** 日本国内におけるマイクロ水力発電・小水力発電のポテンシャルを秘めた地点を、オープンデータを活用して自動的に探索・評価することです。従来は専門家が現地調査や地図手作業で行っていた予備調査を、デジタル技術で効率化・自動化することを目的としています。

**Q: 既存の類似システムとの違いは何ですか？**
**A:** 環境省の「再生可能エネルギー情報提供システム（REPOS）」などはマクロなポテンシャルマップが主ですが、本システムは「具体的な取水点と発電所の位置」をピンポイントで提案する点が特徴です。また、発電ポテンシャルだけでなく、道路からのアクセスや送電線への接続容易性、法的規制（国立公園など）も考慮した現実的なスコアリングを行っています。

## 2. アルゴリズム・ロジック

**Q: 候補地はどのように選定しているのですか？**
**A:** 対象地域をメッシュ（グリッド）状に分割し、各地点の地理的特性（標高、河川までの距離、傾斜など）を評価しています。具体的には以下の3つの要素ごとに適地をスコアリングしています。

1.  **水源**: 高い標高、豊富な流量、河川近接性
2.  **取水口**: 河川沿い、適度な標高、傾斜が緩やか（建設容易性）
3.  **発電所**: 低い標高（落差確保）、アクセス良好、送電線に近い

**Q: どのように最適な「水源-発電所」の組み合わせを見つけていますか？**
**A:** 選定された候補地点群から、総当たりに近い形でペアを作成し、以下の条件でフィルタリングしています。

1.  有効落差が一定以上確保できるか
2.  水平距離が現実的な範囲（長すぎず短すぎず）か
3.  導水管ルート上に保護区域などの障害物がないか
    これらを満たすペアについて、予想発電量や建設コスト指標を算出し、総合スコア順にランキング形式で提示しています。

## 3. データ・精度

**Q: データの出典は何ですか？**
**A:** 全て一般公開されているオープンデータを使用しています。

- **地図・地形・インフラ**: OpenStreetMap (Overpass API) - 河川、道路、送電線、建物、保護区域
- **標高**: Open-Elevation API (SRTMなどのデータ)
- **水文データ**:
  - 国土交通省 水文水質データベース（実測流量）
  - 国土数値情報（流域メッシュ）
  - JAXA ALOS等のDEMデータ（地形解析用）
  - 気象庁 統計データ（降水量）

**Q: データ（特に標高や河川位置）の精度はどの程度ですか？**
**A:** OpenStreetMapやSRTM由来のデータを使用しているため、商用レベルの測量精度はありません。あくまで「概査（プレフィージビリティスタディ）」レベルです。特に標高データには数十メートルの誤差が含まれる場合があるため、有望地点については現地測量や国土地理院の詳細データによる再確認が必須となります。

## 4. 流量推定（技術的詳細）

**Q: 河川の流量はどのように計算していますか？**
**A:** 本システムでは、精度の高い順に多段階のロジックを採用しています（V2/V3アップデート）。

1.  **実測値**: 国土交通省の観測所データがある場合は、その実測値を最優先します（信頼度: 最高）。
2.  **流域面積ベース**: 国土数値情報の流域メッシュデータから集水域面積を取得し、降水量と流出係数を用いて推定します（信頼度: 高）。
3.  **DEM解析**: 数値標高モデル（DEM）を用いて地形解析を行い、集水域を自動生成して面積を算出します（信頼度: 中）。
4.  **簡易推定**: 上記データがない場合、河川の長さから経験則的に流量を推定するフォールバックロジックを使用します。

**Q: 季節変動による渇水期などの流量変化は考慮されていますか？**
**A:** 現状では「年間平均流量」または「平年値」をベースにしています。季節ごとの流量変動（豊水期・渇水期）までは完全にモデル化できていませんが、入力パラメータとして「設備利用率」を変更することで、経済評価への感度分析は可能です。将来的には月別降水量データを組み込む予定です。

## 5. 開発技術・実装

**Q: 使用している技術スタック詳細を教えてください。**
**A:**

- **言語**: Python
- **地理空間処理**: geopandas, shapely (幾何計算), folium (地図可視化), geopy (測地計算)
- **データ取得**: requests (各Web API連携)
- **水文解析**: pysheds (DEM処理・流向解析)
- **科学計算**: numpy, scipy (ガウシアンフィルタ等による平滑化)

**Q: 処理時間はどのくらいかかりますか？**
**A:** 探索範囲（半径）とグリッド解像度に依存します。半径5km程度・グリッド数数百点であれば1〜2分程度で完了します。外部API（Open-Elevation, Overpass API）へのアクセス待ち時間がボトルネックとなるため、並列処理やキャッシング機構（ローカルへのデータ保存）を実装して高速化を図っています。

## 6. 課題・展望

**Q: 法的規制や権利関係は考慮されていますか？**
**A:** 国立公園や自然保護区のデータを取り込み、そのエリア内への施設設置をスコアダウンまたは除外するロジックを実装しています。ただし、水利権や土地所有権、漁業権といった詳細な権利関係はこのシステムでは確認できないため、現地での定性調査が必要です。

**Q: 今後の改良点は？**
**A:**

- **3D地形解析の強化**: 導水管ルートの断面図作成や、より詳細な建設コスト試算。
- **AI活用**: 衛星画像解析による「適地」の特徴学習と自動抽出。
- **リアルタイム性**: アメダス等のリアルタイム降雨データを連動させた発電量予測への応用。

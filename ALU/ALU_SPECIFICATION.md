# ALU（演算装置）仕様書

> **対象デバイス**: Gowin GW1NR-9  
> **記述言語**: Verilog HDL  
> **設計方針**: `always @(*)` を使用せず、感度リストを明示した同期回路設計

---

## 1. 基本アーキテクチャ

### 1.1 データバス幅

| 項目                   | ビット幅 | 説明                                   |
| ---------------------- | -------- | -------------------------------------- |
| データバス             | 8ビット  | 演算データ・即値・レジスタ幅すべて統一 |
| インストラクションバス | 16ビット | SW1〜SW16 で直接入力（加点要素）       |
| アドレス/オペランド    | 8ビット  | 即値オペランド（0x00〜0xFF）           |

> [!NOTE]
> 8ビットデータバスは教育用ALUとして十分な演算範囲（0〜255 / -128〜+127）を持ち、16ビットインストラクションにより最大256種の命令と8ビット即値を同時に指定可能です。

### 1.2 インストラクション形式（SW1〜SW16のビット割り当て）

16ビットのインストラクションを以下のように3つのフィールドに分割します。

```
  SW1                                                SW16
  ┌─────────────────────┬──┬────────────────────────────┐
  │   OpCode (7bit)     │IX│    Operand (8bit)          │
  │  [15:9]             │[8]│   [7:0]                   │
  └─────────────────────┴──┴────────────────────────────┘
```

| フィールド  | ビット位置 | ビット幅 | 説明                                                                                          |
| ----------- | ---------- | -------- | --------------------------------------------------------------------------------------------- |
| **OpCode**  | [15:9]     | 7ビット  | 命令種別（最大128種の命令を定義可能）                                                         |
| **IX bit**  | [8]        | 1ビット  | `0`: オペランド直接参照, `1`: IX レジスタ値とオペランドを加算した値を使用（インデックス修飾） |
| **Operand** | [7:0]      | 8ビット  | 即値データ（0x00〜0xFF）                                                                      |

> [!TIP]
> **IXビットの活用例**: `ADD` 命令で IX=1 を指定し、Operand=0x05 とした場合、実効オペランドは `IX + 0x05` となります。これにより、ループカウンタやオフセット計算が柔軟に行えます。

### 1.3 レジスタ構成

| レジスタ名           | 略称 | ビット幅 | 初期値 | 説明                                         |
| -------------------- | ---- | -------- | ------ | -------------------------------------------- |
| アキュムレータ       | ACC  | 8ビット  | 0x00   | 演算の主対象。全ての演算結果が格納される     |
| インデックスレジスタ | IX   | 8ビット  | 0x00   | アドレッシング修飾用。ループカウンタ等に利用 |
| ステータスレジスタ   | SR   | 4ビット  | 0x0    | 演算結果に応じたフラグを保持                 |

#### ステータスレジスタ（SR）のビット構成

| ビット位置 | フラグ名             | 略称 | 説明                                                            |
| ---------- | -------------------- | ---- | --------------------------------------------------------------- |
| SR[3]      | キャリーフラグ       | CF   | 加算時の桁上がり／減算時のボロー発生時にセット                  |
| SR[2]      | ゼロフラグ           | ZF   | 演算結果が 0x00 のときセット                                    |
| SR[1]      | サインフラグ         | SF   | 演算結果の最上位ビット（MSB）をコピー。符号付き演算での負数判定 |
| SR[0]      | オーバーフローフラグ | OF   | 符号付き演算でオーバーフローが発生した場合にセット              |

## 2. 命令セット一覧

合計 **12命令** を実装します。課題要件の4命令以上を大幅に上回り、S評価に十分な設計です。

### 2.1 命令一覧表

| OpCode [15:9] | 16進 |     命令名     | ニーモニック | 動作内容                           | CF  | ZF  | SF  | OF  |
| :-----------: | :--: | :------------: | :----------: | :--------------------------------- | :-: | :-: | :-: | :-: |
|   `0000000`   | 0x00 |     無操作     |    `NOP`     | 何もしない（ACC保持）              |  -  |  -  |  -  |  -  |
|   `0000001`   | 0x02 |      加算      |   `ADD d`    | ACC ← ACC + d                      |  ✓  |  ✓  |  ✓  |  ✓  |
|   `0000010`   | 0x04 |      減算      |   `SUB d`    | ACC ← ACC - d                      |  ✓  |  ✓  |  ✓  |  ✓  |
|   `0000011`   | 0x06 |     論理積     |   `AND d`    | ACC ← ACC & d                      |  0  |  ✓  |  ✓  |  0  |
|   `0000100`   | 0x08 |     論理和     |    `OR d`    | ACC ← ACC \| d                     |  0  |  ✓  |  ✓  |  0  |
|   `0000101`   | 0x0A |  排他的論理和  |   `XOR d`    | ACC ← ACC ^ d                      |  0  |  ✓  |  ✓  |  0  |
|   `0000110`   | 0x0C | インクリメント |    `INC`     | ACC ← ACC + 1（Operand無視）       |  ✓  |  ✓  |  ✓  |  ✓  |
|   `0000111`   | 0x0E |  デクリメント  |    `DEC`     | ACC ← ACC - 1（Operand無視）       |  ✓  |  ✓  |  ✓  |  ✓  |
|   `0001000`   | 0x10 |     ロード     |   `MOV d`    | ACC ← d                            |  -  |  ✓  |  ✓  |  -  |
|   `0001001`   | 0x12 |     IX転送     |  `MOVIX d`   | IX ← d                             |  -  |  -  |  -  |  -  |
|   `0001010`   | 0x14 |    左シフト    |    `SHL`     | ACC ← {ACC[6:0], 0}。MSBがCFに入る |  ✓  |  ✓  |  ✓  |  0  |
|   `0001011`   | 0x16 |    右シフト    |    `SHR`     | ACC ← {0, ACC[7:1]}。LSBがCFに入る |  ✓  |  ✓  |  ✓  |  0  |

> **凡例**: `d` = 実効オペランド（IX bit=0 のとき Operand[7:0]、IX bit=1 のとき IX + Operand[7:0]）。`✓` = 影響あり、`-` = 変化なし、`0` = クリア。

### 2.2 各命令の詳細動作

#### NOP（0x00）— 無操作

```
ACC ← ACC（変化なし）
```

- 全フラグ不変。デバッグやタイミング調整に使用。

#### ADD（0x02）— 加算

```
{CF, ACC} ← ACC + d     // 9ビットの加算結果
ZF ← (結果 == 0)
SF ← 結果[7]
OF ← (ACC[7] == d[7]) && (結果[7] != ACC[7])
```

- 符号なし・符号付き両方のオーバーフローを検出可能。

#### SUB（0x04）— 減算

```
{CF, ACC} ← ACC - d     // CFはボロー（ACC < d のとき1）
ZF ← (結果 == 0)
SF ← 結果[7]
OF ← (ACC[7] != d[7]) && (結果[7] != ACC[7])
```

- CFがセットされた場合、被減数より減数が大きかったことを示す。

#### AND（0x06）— 論理積

```
ACC ← ACC & d
CF ← 0,  OF ← 0
ZF ← (結果 == 0),  SF ← 結果[7]
```

- ビットマスク操作に使用。特定ビットの抽出に有用。

#### OR（0x08）— 論理和

```
ACC ← ACC | d
CF ← 0,  OF ← 0
ZF ← (結果 == 0),  SF ← 結果[7]
```

- ビットセット操作に使用。

#### XOR（0x0A）— 排他的論理和

```
ACC ← ACC ^ d
CF ← 0,  OF ← 0
ZF ← (結果 == 0),  SF ← 結果[7]
```

- ビット反転やパリティチェックに使用。`XOR 0xFF` で全ビット反転（NOT相当）。

#### INC（0x0C）— インクリメント

```
{CF, ACC} ← ACC + 1
ZF ← (結果 == 0),  SF ← 結果[7]
OF ← (ACC == 0x7F)  // 127→-128 のオーバーフロー
```

- Operandフィールドは無視される。ループカウンタの更新に便利。

#### DEC（0x0E）— デクリメント

```
{CF, ACC} ← ACC - 1
ZF ← (結果 == 0),  SF ← 結果[7]
OF ← (ACC == 0x80)  // -128→127 のオーバーフロー
```

- Operandフィールドは無視。カウントダウンに使用。

#### MOV（0x10）— ロード

```
ACC ← d
ZF ← (d == 0),  SF ← d[7]
```

- CF, OFは不変。即値またはIX修飾値をACCにロード。

#### MOVIX（0x12）— IXレジスタ転送

```
IX ← d
```

- 全フラグ不変。インデックスレジスタに即値をロード。

#### SHL（0x14）— 論理左シフト

```
CF ← ACC[7]
ACC ← {ACC[6:0], 1'b0}
ZF ← (結果 == 0),  SF ← 結果[7],  OF ← 0
```

- 2倍演算として利用可能。MSBがCFに退避される。

#### SHR（0x16）— 論理右シフト

```
CF ← ACC[0]
ACC ← {1'b0, ACC[7:1]}
ZF ← (結果 == 0),  SF ← 結果[7],  OF ← 0
```

- 1/2演算として利用可能。LSBがCFに退避される。

## 3. 表示仕様

### 3.1 実行トリガ

| 信号                 | 割当       | 動作                                                                |
| -------------------- | ---------- | ------------------------------------------------------------------- |
| SW17 (iToggleSw[16]) | 実行トリガ | **立ち上がりエッジ**検出時に現在のSW1〜16のインストラクションを実行 |

> [!IMPORTANT]
> SW17はクロック(iClk)で同期したエッジ検出回路を用いて立ち上がり信号を生成します。チャタリング対策も考慮する必要があります。

### 3.2 7セグメントLED表示切替仕様

SW18（iToggleSw[17]）とS1（iPushSw[0]）の組み合わせにより、表示内容を切り替えます。

| SW18 |     S1     | 表示内容                | 表示詳細                                           |
| :--: | :--------: | ----------------------- | -------------------------------------------------- |
| OFF  | \*（任意） | インストラクション      | SW1〜SW16 の現在値を16進4桁で表示（例：`0x120A`）  |
|  ON  |    OFF     | インデックスレジスタ    | IX の値を16進2桁で表示。上位2桁は `0x00`           |
|  ON  |     ON     | ACC＋ステータスレジスタ | 上位2桁: ACCの値（16進）、下位2桁: SR の値（16進） |

### 3.3 7セグメントLED表示の桁割り当て

```
  千の位    百の位    十の位    一の位
  oDigit[3] oDigit[2] oDigit[1] oDigit[0]
  ┌───┐    ┌───┐    ┌───┐    ┌───┐
  │   │    │   │    │   │    │   │
  └───┘    └───┘    └───┘    └───┘
```

|     表示モード     | 千の位 [3]  | 百の位 [2] |  十の位 [1]   | 一の位 [0] |
| :----------------: | :---------: | :--------: | :-----------: | :--------: |
| インストラクション | Inst[15:12] | Inst[11:8] |   Inst[7:4]   | Inst[3:0]  |
|       IX表示       |    `0x0`    |   `0x0`    |    IX[7:4]    |  IX[3:0]   |
|     ACC+SR表示     |  ACC[7:4]   |  ACC[3:0]  | `0x0` + SR[3] |  SR[2:0]   |

> [!NOTE]
> ACC+SR表示モードでは、十の位にSR[3]（CFフラグ）を表示し、一の位にSR[2:0]（ZF, SF, OF）を表示します。これによりACCの8ビット値とSRの4ビット値を同時に確認できます。

## 5. 評価を高めるためのポイント（考察材料）

### 5.1 命令セット選定の理由

本ALUの12命令は、以下の4つの観点から実用的かつ教育的意義の高い命令群を選定しました。

#### (1) 算術演算グループ（ADD, SUB, INC, DEC）

- **実用性**: 加減算はあらゆるプログラムの基本であり、INC/DECはループカウンタ操作に不可欠。
- **教育的意義**: キャリー・ボロー・オーバーフローの発生条件を理解できる。特にOFフラグの生成回路は符号付き演算の概念を深く学べる。

#### (2) 論理演算グループ（AND, OR, XOR）

- **実用性**: ビットマスク（AND）、ビットセット（OR）、ビットトグル/比較（XOR）はレジスタ操作の基本。`XOR 0xFF` によるNOT演算の代用は命令数削減の工夫。
- **教育的意義**: 論理ゲートレベルの動作と命令レベルの動作を関連付けて学べる。

#### (3) シフト演算グループ（SHL, SHR）

- **実用性**: 2のべき乗の乗除算に利用可能。シリアル通信のビット操作にも不可欠。
- **教育的意義**: バレルシフタの原理を理解し、CFへのビット退避で桁あふれの概念を学べる。

#### (4) データ転送グループ（MOV, MOVIX, NOP）

- **実用性**: レジスタへの初期値設定は全演算の前提。MOVIXによるIXレジスタの独立設定でインデックス修飾を活用可能。
- **教育的意義**: NOP命令はパイプライン設計やタイミング制御の基礎概念につながる。

### 5.2 インデックス修飾方式（IXビット）の意義

- **命令の柔軟性**: 1ビットのIXフィールドにより、同じ命令でも直接オペランドとインデックス修飾を切り替え可能。実質的に命令数が2倍に拡張。
- **設計の簡潔さ**: 複雑なアドレッシングモードを追加せず、1ビットの制御で実現できるため、回路規模を抑えつつ機能性を向上。

### 5.3 ステータスレジスタの4フラグ構成

CF, ZF, SF, OF の4フラグは、実際のCPU（x86, ARMなど）と同等の構成です。

- **CF**: 多倍長演算への拡張可能性を示す
- **ZF**: 比較演算（SUBでZF=1なら等しい）に利用可能
- **SF + OF**: `SF ⊕ OF` で符号付き比較の大小判定が可能

この4フラグにより、教科書レベルのCPUアーキテクチャと整合性のある設計を実現しています。

### 5.4 加点要素への対応

| 加点要素                            | 対応方法                                                                |
| ----------------------------------- | ----------------------------------------------------------------------- |
| SW1〜16によるインストラクション入力 | 16ビットインストラクション形式を採用し、SW1〜16で直接命令をバイナリ入力 |
| 4命令以上                           | 12命令を実装（要件の3倍）                                               |
| インデックスレジスタの活用          | IXビットによるインデックス修飾を全演算命令で利用可能に                  |

## 6. 動作フロー概要

```
1. ユーザーがSW1〜SW16で16ビットインストラクションをセット
2. SW17をON → 立ち上がりエッジ検出
3. インストラクションをデコード（OpCode / IX / Operand を分離）
4. IXビットに応じて実効オペランドを計算
5. OpCodeに基づき演算を実行、結果をACC（またはIX）に格納
6. ステータスフラグ（CF, ZF, SF, OF）を更新
7. SW18/S1の状態に応じて7セグメントLEDに表示
```
